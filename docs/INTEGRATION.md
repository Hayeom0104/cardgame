# 덱 개편 통합 기록

사용자가 전달한 `cardgame-deck-refresh.zip`을 원격 브랜치
`claude/new-session-m5fo91`의 `a643a476`과 비교해 통합했다.
기존 전쟁북 발행 오류 수정과 확장 카드 비용 정리는 그대로 보존했다.
텍스트 줄바꿈은 저장소 기준 LF로 통일했다.

## 적용된 흐름

캐릭터 카드 획득은 플레이 가능한 캐릭터와 기본 스킬 묶음을 해금한다.
스킬 카드는 한 번 해금하면 캐릭터의 속성 규칙에 따라 여러 장 편성한다.
중복 획득은 기존 조각/와일드카드 규칙으로 처리하며, 덱 장수와 분리한다.
캐릭터별 기본 11장과 선택 스킬 7장을 저장하고 출발 때 런에 복사한다.
카드 0~5 강화와 장비 장착·강화는 기존 영구 성장 기록을 유지한다.
모험에서 얻는 체험 카드는 해당 런에만 들어간다.

월드 1은 대족장·대주술사·철갑대장 중 하나를 준비 단계에 예고한다.
준비 취소로 보스가 바뀌지 않고 출발 때 해당 런에 고정한다.

## 실제 확인

- 2026-09-17 최종 통합 검증: **887 passed**, 252.24초.
  Starlette TestClient의 httpx 사용 중단 예고 경고 1건이 있으며 실패는 없다.
  새 DB 스키마 9 초기화와 §10.5 콘텐츠 검사도 재확인했다.

- 첫 전체 실행은 885개 통과, 튜토리얼 실제 플레이 1개 실패였다.
  기록된 시드 `6110960433128140531`에서 월드 1 전투 이벤트가 튜토리얼에
  등장해 같은 3인 적 전투를 반복하는 것을 DB로 확인했다.
  전투 이벤트의 월드 일치 검사를 추가했고, 같은 시드의 실제 플레이와
  개편 테스트 21개를 통과했다. 튜토리얼의 수치나 지도 기획은 바꾸지 않았다.

- 집중 테스트 198개 통과: 덱 장수/저장, 수집 지급, 카드 강화.
- 새 DB: 스키마 9 초기화, 콘텐츠 발행 및 검사 통과.
- 이전 코드로 만든 스키마 8 DB에 전용 업데이트 CLI 실행, 버전 2 발행.
- 기존 콘텐츠 지문, 진행 중 런의 카드와 콘텐츠 버전, 카드 +2 강화 보존 확인.
- `tools/preview_deck_refresh.py`로 동일 데이터의 변경 전후 덱/장비 화면 출력.
  `docs/previews/before/`, `docs/previews/after/`에 저장했다.
- ZIP의 기존 미리보기와 Windows 검증 로그는 전달받은 기록으로 보존했다.
  `CHANGE_MANIFEST.json`의 해시는 원본 ZIP 기준이다.

## 운영 반영과 남은 검증

운영 서버에는 접속하거나 배포하지 않았다. 서버 담당자는 DB 백업 후
`python -m app.cli.upgrade_deck_refresh --db <운영 DB 경로>`와
`python -m app.cli.check_content --db <운영 DB 경로>`를 실행해야 한다.
`bootstrap --force`로 관리자가 편집한 콘텐츠를 덮어쓰지 않는다.

원본 인수인계의 보스 자동 플레이 결과는 최종 밸런스 판정이 아니다.
기존 대족장과 신규 보스의 난도 차이, 실제 Discord 전송/클릭 검증은 남아 있다.
