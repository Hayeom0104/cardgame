# 검증 결과

> 아래 Windows 결과는 사용자가 전달한 ZIP의 검증 기록입니다.
> GitHub 통합 후 이 환경에서 다시 실행한 결과는 `INTEGRATION.md`를 참고하세요.

- 최종 전체 테스트: **886 passed**, 1 warning, 527.65초.
- 경고: 설치된 Starlette TestClient의 httpx 사용 중단 예고. 테스트 실패는 없습니다.
- 원본 전체 테스트: 863 passed / 4 failed. 원본 실패는 Windows CP949가 Git UTF-8 출력을 읽는 문제였으며 수정본에서 해결했습니다.
- 신규 및 갱신된 테스트는 정확한 덱 장수, 저장과 스냅샷, 신규/기존 계정 지급, 임시 체험,
  보스 선정 및 페이즈 효과, 기존 DB 마이그레이션, UI 경로와 렌더링을 검사합니다.
- 원본 스키마 8 DB로 별도 업그레이드 실험 완료: 스키마 9, 신규 콘텐츠 버전 2 발행, 콘텐츠 검사 통과.
- 진행 중인 런은 콘텐츠 버전 1과 원래 36장 덱을 유지했습니다. 기존 콘텐츠 지문과 캐릭터 성급이 일치하고, 기본 스킬 소급 지급으로 조각이 생성되지 않았습니다.
- 실제 게임 렌더러로 덱/장비/신규 보스 PNG를 생성하고 시각적으로 확인했습니다.

검증 환경: Windows, Python 3.12, pytest 9.1.1.
Windows 임시 파일의 많은 동기 쓰기로 인한 지연을 줄이기 위해, 테스트 실행용 외부 래퍼에서만
임시 SQLite 연결의 synchronous를 OFF로 설정했습니다. 배포 코드의 SQLite 내구성 설정은 변경하지 않았습니다.
별도 기존 DB 업그레이드 CLI 검증은 배포 코드 그대로 실행했습니다.

시뮬레이션의 조건과 한계, 기존 대족장 난도 확인 사항은 `DECK_REFRESH_HANDOFF.md`에 기록했습니다.
실제 운영 Discord/Central Bot 연동 검증과 최종 플레이 밸런스 판정은 포함하지 않습니다.
