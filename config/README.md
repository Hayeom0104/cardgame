# 설정 파일

게임의 모든 수치가 여기 있습니다. 코드를 고치지 않고 이 파일들만 바꾸면
됩니다. 설정마다 무엇을 바꾸는 값인지 바로 위에 주석으로 적어 두었습니다.

## 어떤 파일을 열어야 하나요

| 파일 | 바꾸는 것 |
| --- | --- |
| `01_전투.toml` | 카드를 몇 장 뽑는지, 피해가 얼마나 들어가는지, 캐릭터와 적의 기본 능력치, 보스 페이즈 |
| `02_상태이상.toml` | 화상·기절·공격력 증가 같은 지속 효과의 세기와 지속 시간 |
| `03_적_행동.toml` | 적이 아군 중 누구를 노릴지 |
| `04_뽑기.toml` | 확률, 천장, 뽑기 가격, 중복 보상 |
| `05_성장.toml` | 성급·카드 업그레이드·연구·장비 강화에 드는 비용 |
| `06_경제.toml` | 재화가 들어오는 양, 상점 가격, 아이템이 떨어질 확률 |
| `07_맵과_이벤트.toml` | 지도의 모양, 칸 구성, 휴식·보상·저주 |
| `08_튜토리얼.toml` | 첫 월드의 난이도와 보상 |
| `09_런_운영.toml` | 계정 시작값, 방치된 런 정리, 실패한 런의 물건 보존 |

"얼마나 강해지는가"는 `01_전투.toml`, "그렇게 되는 데 얼마가 드는가"는
`05_성장.toml` 에 있습니다.

## 파일을 열지 않고 훑어보기

```
python -m app.cli.show_config          # 전체 (99개)
python -m app.cli.show_config 뽑기      # 파일 이름으로 좁히기
python -m app.cli.show_config pity     # 설정 이름으로 좁히기
```

설명은 파일의 주석을 그대로 읽어옵니다. 주석을 고치면 이 출력도, 관리
대시보드도 함께 바뀝니다 — 설명이 두 곳에 따로 있지 않습니다.

## 적는 방법

```toml
# 자기 턴이 시작될 때 자동으로 뽑는 카드 수입니다.
# 올리면 매 턴 선택지가 늘어나 전투가 쉬워지고, 덱이 빨리 소모됩니다.
draws_per_turn = 3
```

- **설명은 설정 바로 위에** 적습니다. 사이에 빈 줄이 있으면 그 주석은
  설명이 아니라 칸막이로 봅니다.
- **빈 값은 `"없음"`** 이라고 적습니다. TOML에는 빈 값이 없어서 정한
  약속입니다. 예: `duration = "없음"` (시간으로는 사라지지 않음)
- **한글 이름은 따옴표로 감쌉니다.** `"공격형" = { hp = 65 }`
- **낱개 설정을 먼저, `[대괄호]` 설정을 나중에** 적습니다. TOML 규칙상
  `[대괄호]` 가 한 번 나오면 그 뒤의 값은 모두 그 항목의 내용이 됩니다.
- **같은 설정을 두 파일에 적으면 서비스가 뜨지 않습니다.** 어느 쪽이 이겼는지
  알 수 없는 상태로 넘어가지 않게 일부러 막아 둔 것입니다.

## 바꾼 값이 언제 반영되나요

파일은 **새 콘텐츠 버전을 만들 때 심는 기본값**입니다. 실제로 게임이 읽는
곳은 데이터베이스이고, 그 값은 콘텐츠 버전에 고정되어 있습니다.

```
config/*.toml  ──▶  balancing_constants  ──▶  게임
                    (콘텐츠 버전에 고정)
```

그래서 **이미 진행 중인 런은 흔들리지 않습니다.** 누군가 전투 도중에
피해 배율을 바꿔도, 그 런은 시작할 때의 수치로 끝까지 갑니다.

바꾼 값을 적용하려면 새 콘텐츠 버전을 발행하세요. 확률처럼 민감한 값은
특히 그렇게 하는 편이 안전합니다.

## 값을 확인하고 싶을 때

```
python -m app.cli.check_content        # 콘텐츠 검사 (§10.5)
python -m pytest tests/test_config.py  # 설정끼리 어긋나지 않는지 검사
```

`tests/test_config.py` 는 서로 맞물려야 하는 값들을 확인합니다. 예를 들어
기본 덱 구성의 합이 덱 크기와 같은지, 뽑기 확률의 합이 1인지, 튜토리얼
보상이 뽑기 1회 비용보다 넉넉한지 같은 것들입니다. 값을 바꾼 뒤 이 테스트가
깨진다면, 함께 바꿔야 할 다른 값이 있다는 뜻입니다.
